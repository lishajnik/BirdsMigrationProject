# BirdsMigrationProject
# Техническое задание: Love Birds Forever (Орнитологический мониторинг)

## 1. Название и концепция
**Love Birds Forever** — аналитический веб-сервис для орнитологов, исследователей экологических служб и волонтеров, занимающихся мониторингом миграции птиц.

**Проблема:** В периоды климатических изменений критически важно фиксировать аномалии в поведении фауны. Анализировать сырые логи вручную тяжело. Сервис автоматически агрегирует данные орнитологических наблюдений, сопоставляет их с текущими метеорологическими параметрами региона, рассчитывает математические аномалии популяции и визуализирует предиктивные тренды перелетов.


## 2. Модели данных
Несмотря на использование легковесной СУБД SQLite и архитектуры SPA, структура данных строго нормализована на уровне приложения и разделена на 3 логические кастомные модели :

1. **BirdSpecies (Категории видов птиц):**
   * `bird_name` (TEXT, Первичный ключ) — Уникальное орнитологическое название вида.
   * Контролирует агрегированные показатели популяции: пиковая численность в одной стае (`max_flock`), общий объем выборки записей.
2. **MeteoParameters (Климатические параметры среды):**
   * `temperature` (REAL) — Показатель температуры воздуха (°C) в момент фиксации миграционного потока.
   * `wind_speed` (REAL) — Скорость ветра (км/ч). Используется для выявления метеозависимости.
3. **MigrationSighting (Запись миграционного лога и аномалий):**
   * `id` (INTEGER, PK AUTOINCREMENT) — Идентификатор записи.
   * `bird_count` (INTEGER) — Количество замеченных особей в стае.
   * `latitude` / `longitude` (REAL) — Географические координаты точки наблюдения.
   * `is_anomalous` (INTEGER, 0 или 1) — Флаг математического отклонения, рассчитанный алгоритмом Z-Score.

**Связи и логика:** Сущности `BirdSpecies` и `MeteoParameters` логически связываются через транзакционную таблицу `MigrationSighting`, формируя историю наблюдений. На уровне Pandas-аналитики данные группируются по видам для вычисления коэффициентов корреляции.

## 4. Основные сценарии
1. **Орнитолог запускает синхронизацию:** Вводит API-токен сети eBird и код региона ➔ Бэкенд запрашивает последние данные перелетов ➔ В случае сбоя сети или отсутствия ключа автоматически включается отказоустойчивая симуляция данных.
2. **Автоматическая детекция аномалий:** Система рассчитывает среднее арифметическое (`mean`) и среднеквадратичное отклонение (`std`) размеров стай. Записи, где `Z-Score > 1.5`, автоматически маркируются в базе данных флагом `is_anomalous = 1`.
3. **Анализ метеозависимости (Корреляция Пирсона):** На вкладке «Статистика» бэкенд на лету рассчитывает линейную корреляцию между размером стаи и скоростью ветра/температурой, формируя динамический «Индекс чувствительности» для каждого вида птиц.
4. **Сложный SQL-анализ (Для комиссии):** Система выполняет вложенный подзапрос к SQLite, агрегирует данные через `HAVING` и выводит ТОП-3 аномальных видов птиц, чья численность строго превышает средние показатели по всей популяции.
5. **Прогнозирование трендов:** На основе исторических данных NumPy вычисляет среднеквадратичный прогноз активности перелетов для различных диапазонов ветра и строит интерактивные графики.
6. **Экспорт отчетов:** Исследователь нажимает кнопку экспорта ➔ библиотека OpenPyxl на лету генерирует структурированную Excel-таблицу со всеми логами из базы данных.

## 6. Изменения в ходе реализации
1. **Архитектурный сдвиг:** Вместо монолитных HTML-шаблонов проект реализован по современной архитектуре разделения ответственности (Decoupled Architecture): выделенный REST API на Flask + автономный фронтенд на React.js.
2. **Отказоустойчивость API:** Внедрен блок автоматической симуляции орнитологических данных на базе NumPy, если eBird API возвращает ошибку или токен пользователя недействителен.
3. **Усложнение аналитики:** Ручной расчет Z-Score заменен на быстрые векторные вычисления средствами Pandas, что значительно увеличило скорость обработки больших выборок.
4. **Оптимизация интерфейса:** Все тяжелые расчеты перенесены на сторону бэкенда Flask, фронтенд React получает чистый, готовый к отрисовке JSON-пакет, включая данные сложного SQL-подзапроса топ-аномалий.
